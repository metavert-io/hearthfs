# Changelog

## Unreleased

- **Security: dependencies patched for nine RustSec vulnerabilities and
  two soundness bugs.** rustls 0.23.46, rustls-webpki 0.103.16 and
  webpki-roots 1.0.11 fix TLS flaws in the HTTPS client the Voyage
  embedder uses (handshake messages accepted across encryption levels, a
  downgrade to classical key exchange, distrusted intermediates and roots
  accepted, session secrets in `Debug` output). Also h2 0.4.20,
  crossbeam-epoch 0.9.21, tract 0.21.19, tokio 1.54.1 and anyhow 1.0.104.
  CI now checks Cargo.lock against the RustSec database when dependencies
  change and every week.
- **Security: the NFS server is loopback-only.** It now binds 127.0.0.1
  and the kernel mounts `127.0.0.1:/`. Until now it bound 0.0.0.0 and
  mounted through the machine's LAN IP (a workaround for an early macOS 26
  build that refused loopback NFS mounts), so anyone on the same network
  could read a mounted source, including a Hearthloom brain. Loopback
  mounts work on macOS 26.5.2. The startup log now reports the address
  actually bound (it used to say 127.0.0.1 while listening on all
  interfaces), and tests fail if the listener becomes reachable through a
  non-loopback address.

- **Security: `.env` files are no longer indexed** (`.env`, `.env.*` and
  `*.env`; templates such as `.env.example` still are), so credentials
  cannot surface in `@search` snippets. The next scan of an existing mount
  drops any `.env` entries an older version had indexed.

- `SECURITY.md`: how to report a vulnerability privately, and what
  HearthFS does to protect your data.

- **FSKit signing is per developer.** No team ID or bundle ID is
  committed any more: copy `fskit/Local.xcconfig.example` to
  `fskit/Local.xcconfig` (gitignored) and set `DEVELOPMENT_TEAM` and
  `HEARTHFS_BUNDLE_PREFIX`. The app's bundle ID is the prefix and the
  extension's is `<prefix>.fskit`; the app reads the extension's ID at
  runtime and the extension logs under its own bundle ID.
  `fskit/HearthFS.xcodeproj` is generated by build.sh instead of being
  tracked, and build.sh stops early when no team is set. The app finds the
  `hearthfs` CLI through a configured path (`defaults write <app id>
  hearthfs.cliPath …` or `$HEARTHFS_CLI`), PATH, or the usual install
  folders, instead of one developer's checkout path.

- `scripts/fetch-model.sh` downloads the local embedding model
  (all-MiniLM-L6-v2, Apache-2.0) from Hugging Face at a pinned revision
  and checks SHA-256 hashes. `THIRD-PARTY-NOTICES.md` covers the bundled
  C code (SQLite, Oniguruma, tree-sitter and its grammars), the Rust crates
  in `Cargo.lock` (now committed) and the model; `deny.toml` is the
  licence allow-list for `cargo deny`.

- **Retrieval eval for any corpus.** `examples/retrieval_eval.rs` and
  `scripts/eval/` take any folder of corpora (each a `question.json` plus
  `data/`, format in `docs/retrieval-eval.md`), settings are
  `HEARTHFS_EVAL_*` environment variables, and a small invented sample
  corpus ships in `eval/fixtures/` (`cargo run --release --example
  retrieval_eval -- eval/fixtures`). The eval's default fusion weight now
  follows the embedding backend like production does, and all-gold@20 is
  measured over the top 20 again (since hit@40 was added it had counted
  the top 40).

- **Fixed the wedged-mount hang** (incident 2026-07-17: every op on the
  mountpoint blocked in uninterruptible kernel wait and froze the
  hearthloom daemon). Three-part hardening of the NFS mount lifecycle:
  mounts are now `soft,deadtimeout=15` so a dead server yields errors,
  never indefinite hangs; a stale mount left by an unclean death is
  force-unmounted at startup (mounting over it was the wedge); SIGTERM/
  SIGINT unmount before exit so clean stops leave no stale state. Plus a
  startup self-check: after mounting, the server proves a read through
  the kernel answers within 10s or it unmounts and exits nonzero —
  launchd shows a failure instead of a silent landmine. `mount_nfs`
  failure is now fatal (was warn-and-continue). Verified: fresh mount,
  kill-9 → respawn over stale state, SIGTERM cleanliness.

- **Cloud Hearthloom brains**: the `hearthloom` adapter now takes https
  URLs (`hearthloom+https://host` scheme; wizard's Brain URL field accepts
  e.g. `https://brain.example.com`), and an optional **Key name**
  field so a cloud brain's PAT can live separately from the local one
  (`hearthfs auth <name>`; resolution: `--api-key` > named key > default
  hearthloom key).

## 0.1.2 — 2026-07-11

Three more adapters — breadth without the connector war:

- **`git`**: clone-and-index any git repository (GitHub/GitLab/Bitbucket/
  self-hosted, public or private via your own git credentials). Shallow
  clones under `~/.hearthfs/clones/`, refreshed on mount, served
  last-fetched when offline. Full local semantic search — better retrieval
  than the API-delegated `github` adapter.
- **`mcp`**: mount any Model Context Protocol server's resources as files
  (stdio command or Streamable HTTP, with the initialize handshake,
  paginated `resources/list`, text+blob reads). Local indexing is ON —
  MCP servers gain semantic search they don't natively have. Verified
  end-to-end against `@modelcontextprotocol/server-everything`
  (`@search` over MCP resources works).
- **`api`**: the open integration point — mount anything that serves a
  HearthFS discovery manifest (`--manifest-path`, optional named key via
  `--auth-service`). Verified by mounting Hearthloom through the generic
  path. Serve the manifest, get mounted.
- `hearthfs auth <name>` now accepts custom key names (referenced from
  `api`/`mcp` volumes' Key-name field); keys stay in 0600 files, never in
  volumes.json, never on argv.

## 0.1.1 — 2026-07-11

The "mount everything" release: FSKit becomes the native macOS transport,
and HearthFS grows an adapter framework for second brains and GitHub.

### Added
- **Adapter registry + volumes** (`8e56709`): six adapters — `folder`,
  `obsidian` (vault auto-discovery), `logseq`, `gbrain` (mounts the brain's
  markdown git repo directly), `hearthloom`, `github`. Volume configs
  persist in `~/.config/hearthfs/volumes.json`; `hearthfs volume
  add/list/remove/mount/unmount`, `hearthfs adapters [--json]`.
- **Volumes UI**: a Volumes section + add-volume wizard in the macOS app,
  rendered from the CLI's registry JSON and driving the CLI for every
  operation — UI/CLI parity by construction. (Ships with the next app
  install.)
- **GitHub adapter** (`hearthfs-source-github`): browse/read configured
  repos via the REST contents API; search delegated to GitHub code search;
  fine-grained PAT via `hearthfs auth github`.
- **Hearthloom smart source** (`f151281`): mount your Hearthloom brain
  (BRAIN.md, entity dossiers, day recall, goals) — always the vault-locked
  view. `hearthfs auth hearthloom` key UX (0600, stdin-prompted).
- **`@fit` → server-side budget passthrough** (`Source::read_fit`): on
  smart sources, `file@fit/<n>` sends `?budget=n` to the origin instead of
  fetching everything and trimming locally.
- **OS-version gate** in the onboarding wizard: macOS below 26.5.2 gets an
  update banner + Software Update deep-link instead of a hanging mount.
- Live integration test against a running Hearthloom daemon
  (`tests/live_brain.rs`; skips when no key/daemon).

### Changed
- **FSKit is the default mount transport on macOS 26+** (`3a2d30b`),
  decided by benchmark: cold-read p95 1.99× the NFS path at sub-ms
  absolute; warm/readdir stay on NFS for the benchmark harness. Full
  numbers in `docs/benchmarks.md`.
- `fskit/build.sh` rewritten around the working signing flow (arm64 cargo
  target, automatic signing, LaunchServices-registration eviction);
  `--install` gates the enablement-breaking step.
- README repositioned: product pitch, why-a-filesystem, adapters table,
  Claude Code usage, FSKit-vs-FUSE differentiator.

### Fixed
- ApiSource: duplicate or empty collection slugs corrupted NFS READDIR
  replies; plain-path collection nodes (list+item template) never resolved
  item reads (`8c2da03`). Both found by the live brain test.
- Volume names derived from dot-directories (`~/.gbrain`) no longer
  produce hidden mountpoints (`456d27f`).
- `hearthfs volume list | head` no longer panics on SIGPIPE.

## 0.1.0 — 2026-07-07 (baseline)

- Local filesystem indexing: chunked FTS5 (BM25, 6× path weighting),
  tree-sitter structure, optional local ONNX embeddings (parallelized) or
  opt-in Voyage backend; per-chunk indexes that survive 10k-file corpora.
- Magic paths: `@search`, `@fit/<budget>`, `@section`, `@outline`,
  `@tokens`; fused search output with token counts and next-step hints.
- Mount transports: pure-Rust NFSv3 server (macOS Tahoe LAN-IP
  workaround), FSKit appex (verified end-to-end on macOS 26.5.2).
- Retrieval eval harness: a free retrieval tier (hit@k, MRR over gold
  files) and a paid agent tier (tokens per correct answer, raw folder vs
  mount).
